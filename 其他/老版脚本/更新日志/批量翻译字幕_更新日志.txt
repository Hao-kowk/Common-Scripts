批量翻译字幕  更新日志
====================
文件：批量翻译字幕_vX.py（入口：cmd版\批量翻译字幕.bat）
用途：把 .srt 字幕翻成中文（或指定语言），时间轴原样保留，不用申请 API Key

v1.0  2026-09-26
  初版。起因是自己的录播要翻成中文，微软那条免 Key 通道（Edge auth）已经 404，
  LibreTranslate 公共实例也全挂了，于是内置三个还能用的免费引擎：
  transmart（腾讯，默认）/ youdao / google。
  1. 多线程 + 批量请求，10280 条字幕几分钟跑完；整批行数对不上会自动回退逐行翻译
  2. 翻译缓存放 %LOCALAPPDATA%\SubtitleTranslate，中断重跑不重复请求，
     也不会在脚本目录（git 仓库）里多出文件
  3. 输出纯译文 .zh.srt 和中英对照 .zh.bilingual.srt
  4. 时间轴、序号、条数原样保留；实测 10280 条零偏移、无空行、无截断

v1.1  2026-09-26
  修「很多没翻译」。起因：第二个视频那份字幕翻完，2415 条里有 202 条英文一个字没动。
  1. 查明原因：腾讯这个免费接口会静默降级——偶尔把原文原样吐回来，ret_code 还是 succ，
     返回值上完全看不出错；而 v1.0 没做校验，还把这个假结果写进了缓存，
     于是重跑也翻不出来（缓存命中，脏数据被固化）
  2. 新增校验：译文和原文一字不差、且原文是英文 → 判定为假成功，逐条单独重试
  3. 重试后确实翻不出来的（单字母、乱码、专有名词）不写进缓存，下次重跑还会再试
  4. 缓存自动修复：读到这类脏数据直接删掉当没命中，不用手动清缓存
  5. 兜底：单字母/纯符号直接跳过不浪费请求；整批请求失败会逐条救，
     救不回来保留原文并计数——v1.0 是一个批次出错就把整个运行搞崩
  6. 新增 --no-verify，跳过校验（跑得快一点）
  实测：同一份字幕，英文没翻的从 202 条降到 14 条
  （剩下的是 si / E / w / Anywho / Yeah yeah yeah 这类，接口本身就不给翻）
